# Запрос увеличения квот Yandex Cloud — vibekodik prod

## Как подать
1. Открой [console.yandex.cloud → Квоты](https://console.yandex.cloud/folders/b1gdrsc5c0l86vvjs95l/quotas).
2. Слева выбери service: **Compute Cloud**.
3. Найди нужные квоты и нажми «Запросить увеличение». Для каждой укажи новое значение и причину из таблицы ниже.

## Compute Cloud

| Квота | Сейчас | Запросить | Почему |
|---|---|---|---|
| Количество vCPU | 32 | **48** | Нужно 30.4 (LB 2 + Backend×2 8+8 + Frontend 8 + DB 4 + Relayer 0.4). 32 — впритык, без запаса на тестовые VM или будущий рост. |
| Количество ВМ | 12 | **20** | Сейчас 1 (relayer-01), будет 5 (LB, app×2, frontend, DB) + bastion при необходимости + запас на CI/staging машины. |
| Размер дисков IO-M3 (3 реплики) | 186 GB | **600 GB** | DB (MySQL 8.4 + Redis) — 350 GB основной + 100 GB binlogs/backups = 450 GB. Тип IO-M3 потому что DB критична, нужны 3 реплики. |
| Размер NRD дисков (без реплик) | 558 GB | **800 GB** | App backend×2 (200 GB) + Frontend (100 GB) = 372 GB. Округление NRD кратно 93 GB — фактически 558 GB впритык. Запас на staging/тесты. |
| Размер network-ssd (обычные) | 200 GB | **500 GB** | LB (40 GB) + bastion если будет (15 GB) + запас. |

## VPC

| Квота | Сейчас | Запросить | Почему |
|---|---|---|---|
| Статические внешние IP | 2 | **4** | LB (1) + relayer-01 (1) + bastion если будет (1) + запас. |

## Обоснование (для всех — общий текст)

> Разворачиваем production-инфраструктуру AI-платформы vibekodik (FastAPI/uvicorn backend, frontend, MySQL 8.4 + Redis, nginx LB с TLS termination). 4 VM core + LB + bastion. Текущие квоты не покрывают нужный объём (особенно SSD IO-M3 для DB — 186 GB при потребности 450 GB). Проект коммерческий, биллинг активен.

## После одобрения
Yandex обычно отвечает в течение 1-4 часов рабочего времени. Когда квоты подняты — продолжаем создавать VM по подготовленному плану.
